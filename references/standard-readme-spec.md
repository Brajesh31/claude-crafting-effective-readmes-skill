# README Structure Specification

This is a practical checklist, not a mandatory universal format. Use only sections that help the intended reader.

## Identity

- Repository or project name is clear.
- Opening description states the problem solved and intended audience.
- Project status is accurate.
- Badges are current and meaningful.

## Use

- Prerequisites are explicit.
- Installation steps are complete and ordered.
- Quickstart demonstrates a real successful path.
- Examples match current APIs and command names.
- Configuration names, defaults, and secret handling are accurate.

## Operate

- Common workflows are documented.
- Errors and troubleshooting steps are actionable.
- Compatibility and known limitations are stated.
- Security-sensitive configuration is handled safely.

## Contribute

- Development setup is reproducible.
- Test and lint commands are provided.
- Contribution expectations are clear.
- Support channels are correct.

## Quality

- Headings form a logical hierarchy.
- Links and images work.
- Code blocks use language identifiers.
- Tables are readable on narrow screens.
- No placeholders, private data, secrets, or false claims remain.
- Licensing statements match the repository's actual license.

## Suggested review levels

**Essential:** purpose, prerequisites, installation, quickstart.

**Project-dependent:** configuration, API, examples, deployment, troubleshooting.

**Community-dependent:** contributing, code of conduct, support, governance.

**Optional:** roadmap, acknowledgements, badges, screenshots, architecture.
