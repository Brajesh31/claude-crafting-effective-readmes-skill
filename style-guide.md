# README Style Guide

## Prose

- Lead with the answer, not the project's history.
- Use plain language and define necessary technical terms.
- Prefer short paragraphs and active verbs.
- Be precise about supported behavior and limitations.
- Avoid marketing adjectives without evidence.

## Headings

- Use descriptive, parallel headings.
- Keep a logical heading hierarchy.
- Avoid excessive all-caps and decorative emoji.
- Name sections after reader tasks, such as "Install" or "Configure".

## Code

- Label code fences with a language.
- Include only commands that have been checked.
- Use placeholders such as `YOUR_API_KEY` and explain them.
- Do not place real credentials or private URLs in examples.
- Show expected output only when it is representative.

## Links and images

- Use descriptive link text.
- Check links before release.
- Add alt text to useful images.
- Avoid screenshots that are out of date or merely decorative.

## Formatting

- Use bullets for short unordered choices and numbered lists for sequences.
- Use tables for comparisons or structured fields, not prose.
- Keep lines and tables readable on mobile.
- Remove repeated content and unused badges.
